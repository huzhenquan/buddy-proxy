# Koa 下流式响应的状态码是 404（2026-10-22）

## 现象

所有流式请求返回：

```
HTTP/1.1 404 Not Found
x-request-id: req_...
content-type: text/event-stream; charset=utf-8
```

**body 却是一段完全正常的 SSE**（message_start / ping / thinking / content_block_delta）。

客户端读的是状态码，所以 opencode 报：

```
Provider request failed with HTTP 404: event: message_start
data: {"type":"message_start","message":{"id":"...","model":"MiniMax-M3.1-Flash",...}}
```

非流式请求正常（200）。

## 根因

Koa 的 `handleRequest` 在跑中间件链之前把 `res.statusCode` 设成 **404**
（koa/lib/application.js）：

```js
handleRequest(ctx, fnMiddleware) {
  const res = ctx.res;
  res.statusCode = 404;
  ...
```

Koa 只有在自己写响应时才会改成别的状态码（`respond()` 里 `res.statusCode = ctx.status`，
而 `ctx.body` 被赋值时 `ctx.status` 才会变成 200）。

流式响应不走 Koa 的写响应路径 —— 代理自己接管原始 response：

```ts
function takeOver(ctx: Koa.Context): void {
  ctx.respond = false;   // ← Koa 不再写状态行
}
```

`ctx.respond = false` 之后 Koa 的 `respond()` 直接 return，**没有人把 404 改成 200**。
于是 `res.statusCode` 保持 Koa 设的默认值 404，而 `flushHeaders()` 把这个状态行发了出去。

Express 时代没有这个问题：Express 的 `res.writeHead()` 不传状态码时默认 200。

## 修复

```ts
function takeOver(ctx: Koa.Context): void {
  ctx.respond = false;
  // Koa starts every request at 404 and only replaces that when it writes the
  // response itself. A stream writes its own, so nothing would ever say 200
  // and the client would see a 404 with a perfectly good body.
  ctx.status = 200;
}
```

`ctx.status = 200` 走 Koa 的 setter，直接改 `res.statusCode` ✓。

## 为什么自测没抓到

`test/e2e.sh` 原来只看 body 的内容（有没有内容、有没有 usage、思考有没有漏进正文），
**不看状态码**。所以 body 是好的，测试就绿。

现在的自测每次请求都多查一次状态码：

```bash
status=$(curl -s ... -o "$BODY_FILE" -w '%{http_code}')
report "$group/$model $dialect stream status" "2xx" "$(status_class "$status")"
```

验证过这个检查有效：把修复回退后，10 个流式用例全挂（`want=2xx got=4xx`），
恢复后 51/0。

## 教训

- **接管原始 response 时，要自己把状态码设成 200** —— Koa 的默认值是 404，不是 200。
- **端到端测试要查状态码**，不能只看 body。一个"body 正确但状态码错误"的响应，
  在客户端看来就是彻底失败。
- 框架换了以后，这类默认值差异要在交付层统一处理，而不是散落在每个 handler 里。
